# Как проверялась безопасность

Требования раздела «Безопасность» ТЗ проверены двумя независимыми способами: автотестами, которые атакуют базу при каждом прогоне, и отдельным пентестом, который проводила отдельная сессия ИИ-агента (Claude Code), не видевшая тестов.

Главный принцип: все правила живут в базе (RLS, права на колонки, функции и триггеры). Поэтому проверяется не интерфейс, а прямые запросы к Supabase в обход него, с токеном обычного пользователя или вообще без него.

## 1. Автотесты (`tests/security/`)

98 тестов в 8 файлах. Каждый тест входит как настоящий пользователь (постановщик, исполнитель, пользователь без профиля или аноним) и пытается сделать то, что ему запрещено.

| Файл                      | Что проверяет                                                                                                                                 |
| ------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `readIsolation.spec.ts`   | исполнитель видит только свои задачи, их объекты и их историю                                                                                 |
| `taskWrites.spec.ts`      | нельзя задать статус, автора или дату создания; исполнитель — только исполнитель; блокировка полей по статусам; принятую задачу нельзя менять |
| `objectWrites.spec.ts`    | объекты меняет только постановщик; пустые названия отклоняются                                                                                |
| `transitions.spec.ts`     | все разрешённые и запрещённые переходы для обеих ролей; обязательный комментарий; две одновременные попытки сменить статус                    |
| `transitionRules.spec.ts` | таблицу правил переходов нельзя изменить ни одной ролью                                                                                       |
| `history.spec.ts`         | история только для чтения; создание, переходы и удаление попадают в неё                                                                       |
| `profileWrites.spec.ts`   | роль нельзя поменять или выдать себе                                                                                                          |
| `anonymous.spec.ts`       | без входа ничего не читается и не пишется; регистрация закрыта                                                                                |

Тесты писались до реализации защиты. На голой схеме из 79 тестов того момента упали 72: атаки проходили, потому что защиты ещё не было, а не из-за ошибок в самих тестах.

**Проверка теста на одновременные переходы.** Если временно убрать блокировку строки (`for update`) в `transition_task`, тест краснеет: из двух одновременных запросов проходят оба. С блокировкой проходит ровно один.

## 2. Независимый пентест

Пентест проводила отдельная сессия ИИ-агента, которая не видела автотестов, пока не закончила атаки. Работа шла только с локальной базой, после каждого прогона база сбрасывалась начисто. Каждая атака повторена дважды с чистой базы, результаты совпали.

**61 проверка, из них 57 программных атак:**

| Направление            | Что пробовали                                                                                                                                                                                       | Итог                                      |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------- |
| Чтение чужого          | вложенные выборки (`tasks(*)`, объект → задачи → объект), фильтры `or=` и `not=`, подсчёт скрытых строк через `count=exact`, разница ответов для чужого и несуществующего id, GraphQL, `auth.users` | заблокировано                             |
| Статусы в обход правил | прямое изменение статуса, `upsert`, переход чужой задачи, переходы не своей роли, выход из «Принята», возврат на доработку без комментария, две одновременные попытки                               | заблокировано, кроме одной находки (ниже) |
| Подделка полей         | задача сразу «Принята», чужой автор, подменённая дата, исполнителем назначен постановщик или несуществующий пользователь, смена объекта и исполнителя после старта, правка принятой задачи          | заблокировано                             |
| История                | вставка, правка и удаление записей обеими ролями                                                                                                                                                    | заблокировано                             |
| Роли                   | смена своей роли, создание себе профиля, роль через `user_metadata`                                                                                                                                 | заблокировано                             |
| Функции базы           | прямой вызов всех функций схемы под анонимом и исполнителем                                                                                                                                         | заблокировано                             |
| Аноним и регистрация   | чтение и запись всех таблиц без входа, регистрация, вход по ссылке на новый email, анонимный вход                                                                                                   | заблокировано                             |
| Фронтенд и утечки      | HTML и скрипты в названиях и описаниях, секретный ключ и пароли в собранном фронтенде и в истории git                                                                                               | чисто                                     |

### Найдено и исправлено

**Комментарий из одних переносов строк (низкая серьёзность).** При возврате «На доработку» комментарий обязателен. Проверка отбрасывала только пробелы: стандартный `trim()` в PostgreSQL не трогает переносы строк и табуляцию. Комментарий из `\n\t` проходил, и задача уходила на доработку без объяснения.

Изоляцию данных и права это не нарушало, но нарушало прямое требование ТЗ. Исправлено заменой на `btrim(x, E' \t\n\r\f\v')`. Та же замена сделана в проверках обязательных названий объектов, адресов, задач и имён. Добавлены регрессионные тесты на `\n`, `\t`, `\r\n` и остальные пробельные символы.

Автотесты эту дыру не ловили: они проверяли пустой комментарий и пробелы, но не переносы строк. Слепое пятно теста совпало с ошибкой в коде. Именно ради таких случаев атаки придумывал агент, который не писал ни защиту, ни тесты.

### Что осталось вне проверки

- **Облачный проект.** Атаки шли на локальную копию с теми же миграциями. На развёрнутом приложении вручную проверено то, что зависит от облака: регистрация и вход по ссылке на новый email отклоняются (`signup_disabled`), GraphQL в проекте не включён, публикация Realtime пуста, аноним не получает данных, каждая роль видит только своё, переходы в обход правил и правка истории отклоняются, в собранном фронтенде нет секретного ключа.
- **Storage** не используется.
- **Неразрывный пробел (U+00A0)** в комментариях и названиях не считается пустым, это сознательное допущение.
- Стойкость самих токенов Supabase Auth и нагрузочные сценарии вне задачи.
